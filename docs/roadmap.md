# Roadmap

Planned next, not yet specified.

## Next features

- **Feature 008 — Regression replay.** Pick a past run and re-send its exact attacker messages to the target with no attacker model in the loop, judge the replies with the same evidence rules (canary first, then judge), and report whether the target is **still vulnerable** or **fixed**. Turns a finding into a repeatable check you can re-run after a prompt or guardrail change.
- **Feature 009 — Community prompt feed.** A scheduled importer that pulls attack prompts from a pinned allowlist of maintained open-source probe libraries — primary: NVIDIA garak (pinned release tag, probes `dan`, `promptinject`, `latentinjection`, `agent-breaker`); secondary: Microsoft PyRIT datasets and JailbreakBench; static datasets such as `deepset/prompt-injections` only as a one-time seed. Each import checks the licence, takes injection prompts only, caps at a few hundred, dedupes, and tags every prompt to a Kestrel family, then upserts into the shared ChromaDB pool as an **unverified** tier ranked below learned patterns. An unverified pattern is **promoted to verified** once the judge confirms a success using it; unverified patterns with no success are pruned after a configurable number of uses and a minimum age. Regression replay (008) is unaffected — it replays SQLite run records, not the pattern pool. Impact is measured with a 007 experiment: imports on vs off.
- **Agentic QA repository (next phase).** A separate repo holds all of Kestrel's end-to-end test cases. When a feature PR merges here, a GitHub Actions workflow dispatches to that repo (`repository_dispatch` carrying the feature id and a link to the merged spec). There, an agent reads the merged spec and its user stories, drafts test cases per acceptance scenario, and generates Playwright automation against the Streamlit UI and the API (via a Playwright skill). The generated tests open as a PR in the QA repo for human review and approval (human-in-the-loop) before merge. The QA repo then runs those tests on a schedule and on demand against a deployed Kestrel, reporting results back to the feature PR. Keeps test generation, review and execution separate from product code.

## From reviewer feedback

- **Structured logging and tracing** — JSON-lines formatter; log with `extra={...}` fields, never %-interpolation; `run_id` (and `experiment_id`/arm) on every record; events at run start/end, each attacker turn, each target call (`elapsed_s`, status), each judge call (verdict, hard_evidence), memory retrieval (pattern/memory counts, retrieved pattern ids), write-back result, experiment cap hits; never attack text, replies or secrets. LangSmith/OpenTelemetry tracing behind env flags with `run_name` and metadata; test that no header value reaches span attributes. Covers Sprint hard task H2.
- **Versioned prompts** (next spec-driven feature) — judge, recommendation, attacker prompts and family goal sentences in `prompts/<name>.<version>.md` with front-matter; cached `load_prompt`; `judge_prompt_version`/`attacker_prompt_version` on runs and experiment_arms (schema v7), shown in report headers; a prompt-version arm in 007 for A/B on the golden set or a campaign. Goal sentences stay neutral.
- **Retrieval controls** — distance floor, dedupe, query built from attacker messages and judge progress only (never target replies), embedding model recorded in collection metadata and checked in `self_check`, labelled retrieval fixture with recall@k.
- **LangGraph idioms** — typed State with reducers and a typed Outcome, module-level compiled graph with deps via runtime context, AsyncSqliteSaver checkpointer for resumability, optional interrupt-based approve node with an Approve/Stop control in the UI.

## Later

- **OWASP LLM Top 10 — 2026 edition.** Update the mapping in [report/owasp.py](../src/kestrel/report/owasp.py) from the 2025 to the 2026 edition: the same ten risks, reordered — Excessive Agency moves from LLM06 to **LLM03**, and System Prompt Leakage (LLM07) is renamed **Hidden Context Exposure**. Until this lands, the report must state explicitly that it cites the **2025** edition.
- **Second mapping — OWASP Top 10 for Agentic Applications 2026 (ASI01–ASI10).** Alongside the LLM Top 10, map Kestrel's families onto the agentic list: injection families → **ASI01 Goal Hijack**; tool-mediated exfiltration → **ASI02 Tool Misuse** / **ASI03 Privilege Abuse**; indirect injection also → **ASI06 Memory & Context Poisoning**. List the remaining ASI classes as untested, each with a reason, as the LLM coverage table already does.
- **Browser / computer-use target adapter.** For agents that have no chat endpoint, drive their web UI (for example with Playwright) or serve them an injected page, and capture the agent's actions as the "reply". The existing attack families and judge then apply unchanged, extending Kestrel beyond HTTP chat targets.
- **Third-party vulnerable targets.** Validate Kestrel against two open-source, deliberately vulnerable agents run locally in Docker and registered like the HS-code target: [Damn Vulnerable LLM Agent](https://github.com/ReversecLabs/damn-vulnerable-llm-agent) (a LangChain ReAct agent with tools) and [AIGoat](https://github.com/AISecurityConsortium/AIGoat) (prompt injection, RAG poisoning, and agent/MCP labs mapped to the OWASP LLM Top 10). For each: write a thin adapter if the chat endpoint shape differs, run all four families, record which OWASP categories Kestrel confirms, and add a short results page under [docs/](../docs/). Not part of CI — manual validation. Shows Kestrel generalises beyond its own sacrificial target.
- **Product-grade front end on the existing FastAPI API.** The UI is already API-only (the screen holds no logic), so this is a client swap, not a rewrite. Options: **Next.js / React** (the standard, best look, TypeScript), **Reflex** (Python, compiles to React), **NiceGUI** (Python over Vue). Motivation: full layout control, no full-script reruns on every interaction, and a look fit for non-developer users. Streamlit stays as the internal/demo screen until the new front end reaches parity.
