# Roadmap

Planned next, not yet specified.

## Next features

- **LangGraph idioms** (from reviewer feedback) — typed State with reducers and a typed Outcome, module-level compiled graph with deps via runtime context, AsyncSqliteSaver checkpointer for resumability, optional interrupt-based approve node with an Approve/Stop control in the UI.
- **Judge evaluation.** Score the judge's verdicts against runs confirmed by hard evidence — the deterministic items 013 part 1 records give a labelled set without hand grading — reusing the 007 experiment harness and the judge golden set (`tests/eval/judge_samples.json`), and report precision and misses (a hard-evidence success the judge called failed) per family and per judge prompt version.
- **Streamlit UI polish for the capstone.** The run page (headline, evidence section, turn table, replay comparison) and the OWASP report page, so a reviewer can read a finding end to end without the API. Not the product front end — that stays under "Later".
- **Deployment.** Host Kestrel and the HS-code target in hosted mode (`KESTREL_API_TOKEN`, the address guard on), with every secret set outside the repo (environment or a secret store, never a committed file), a release path from `master` (tag → build → deploy), and a short note on how failures are handled (what a failed deploy, a failed start-up self-check or a stuck run looks like, and the recovery step for each).
- **Capstone docs.** A README paragraph with what is new since Sprint 3 (009–013 part 1: versioned prompts, structured logging and tracing, retrieval controls, regression replay, behavioural evidence), and a short `AGENTS.md` mirroring `CLAUDE.md` for agents that read that file instead.
- **Feature 013 — Behavioural evidence, part 2 (tool-call log and honeypot first).** The side channel a cooperating target exposes and the tripwires Kestrel plants without cooperation, on the owned HS-code target first, reusing part 1's `EvidenceChecker` and fixed check order: the **tool-call log** (a canary or sensitive value in a tool argument → hard evidence), the **honeypot tool** (any invocation → hard evidence), the **canary callback listener** (a unique per-run URL planted for the tool-exfiltration family; a hit on Kestrel's own `/callback/{token}` route → hard evidence, at most 100 stored hits per run, the route mounted only when `KESTREL_CALLBACK_BASE_URL` is set), and the **protected-state snapshot** (a before/after diff per turn → hard evidence), plus the side-channel registration, connection test and UI, redaction of callback URLs from every model input, replay re-verification against the copied tokens, the HS-code target's cooperating tools behind an environment flag with a no-default outbound allow-list, and the polish tasks (constitution amendment, docs, the full `traceability.md`). Spec, plan and tasks are merged (#39, tasks T041–T068). **Parked on branch `013-part2-wip`** with T041 to T046 done (the side-channel registration: store table, API fields, connection test with named failure steps, UI form, correlation id on runs, auth value in the mask list); resume by running the full offline suite and rebasing onto `master`.
- **Feature 015 — Community prompt feed.** A scheduled importer that pulls attack prompts from a pinned allowlist of maintained open-source probe libraries — primary: NVIDIA garak (pinned release tag, probes `dan`, `promptinject`, `latentinjection`, `agent-breaker`); secondary: Microsoft PyRIT datasets and JailbreakBench; static datasets such as `deepset/prompt-injections` only as a one-time seed. Each import checks the licence, takes injection prompts only, caps at a few hundred, dedupes, and tags every prompt to a Kestrel family, then upserts into the shared ChromaDB pool as an **unverified** tier ranked below learned patterns. An unverified pattern is **promoted to verified** once the judge confirms a success using it; unverified patterns with no success are pruned after a configurable number of uses and a minimum age. Regression replay (012) is unaffected — it replays SQLite run records, not the pattern pool. Impact is measured with a 007 experiment: imports on vs off.

## Later

- **Behavioural evidence — the kinds the 013 spec put out of scope.** Each needs 013 part 2's side channel or listener first: **off-allow-list tool use** (a per-target allow-list of tools; a tool-call-log entry naming a tool not on the list → hard evidence), **scope or permission escalation** beyond the one honeypot tool (a privileged decoy, or a tool argument crossing a declared scope boundary), **resource-abuse metering** (the target's own tool-call count and cost per run above a threshold — its self-inflicted use, never a Kestrel-driven load test, Principle VIII), and **DNS-based callback tokens** (a resolver to run beside the HTTP listener).
- **OWASP LLM Top 10 — 2026 edition.** Update the mapping in [report/owasp.py](../src/kestrel/report/owasp.py) from the 2025 to the 2026 edition: the same ten risks, reordered — Excessive Agency moves from LLM06 to **LLM03**, and System Prompt Leakage (LLM07) is renamed **Hidden Context Exposure**. Until this lands, the report must state explicitly that it cites the **2025** edition.
- **Second mapping — OWASP Top 10 for Agentic Applications 2026 (ASI01–ASI10).** Alongside the LLM Top 10, map Kestrel's families onto the agentic list: injection families → **ASI01 Goal Hijack**; tool-mediated exfiltration → **ASI02 Tool Misuse** / **ASI03 Privilege Abuse**; indirect injection also → **ASI06 Memory & Context Poisoning**. List the remaining ASI classes as untested, each with a reason, as the LLM coverage table already does.
- **Browser / computer-use target adapter.** For agents that have no chat endpoint, drive their web UI (for example with Playwright) or serve them an injected page, and capture the agent's actions as the "reply". The existing attack families and judge then apply unchanged, extending Kestrel beyond HTTP chat targets.
- **Third-party vulnerable targets.** Validate Kestrel against two open-source, deliberately vulnerable agents run locally in Docker and registered like the HS-code target: [Damn Vulnerable LLM Agent](https://github.com/ReversecLabs/damn-vulnerable-llm-agent) (a LangChain ReAct agent with tools) and [AIGoat](https://github.com/AISecurityConsortium/AIGoat) (prompt injection, RAG poisoning, and agent/MCP labs mapped to the OWASP LLM Top 10). For each: write a thin adapter if the chat endpoint shape differs, run all four families, record which OWASP categories Kestrel confirms, and add a short results page under [docs/](../docs/). Not part of CI — manual validation. Shows Kestrel generalises beyond its own sacrificial target.
- **Product-grade front end on the existing FastAPI API.** The UI is already API-only (the screen holds no logic), so this is a client swap, not a rewrite. Options: **Next.js / React** (the standard, best look, TypeScript), **Reflex** (Python, compiles to React), **NiceGUI** (Python over Vue). Motivation: full layout control, no full-script reruns on every interaction, and a look fit for non-developer users. Streamlit stays as the internal/demo screen until the new front end reaches parity.

## Done

- **006 (amendment) — Honest Spec-PR path for refactor and bug-fix PRs.** A PR that changes `src/` or `ui/` and
  implements no specification declares `Spec-PR: none` with exactly one reason line — `Spec-PR-reason: refactor`
  or `Spec-PR-reason: bugfix: #<issue>` — and the matching PR label (`refactor`/`bugfix`, not the other); a
  `bugfix` issue number is checked to exist in this repository (open or closed) by a live lookup. Everything else
  stays fail-closed, each failure naming the condition and the three accepted forms. `check_traceability.py` reads
  the description and labels live (`gh pr view`) at evaluation time, never from the triggering event, so a manual
  re-run and overlapping runs judge the same current state. A new, non-required `qa-recheck.yml` re-runs only the
  `traceability` job — never `quality` or `review` — when the body is actually edited or the `refactor`/`bugfix`
  label is added or removed; its step machine (`scripts/qa_recheck.py`) classifies a re-run refusal by re-reading
  the run rather than the POST's HTTP code, fails closed on every API error, and posts one fixed-text stale-result
  comment when it cannot refresh the check (a fork PR, GitHub's 50-re-run cap, or a timeout). Replaces the only
  previous way past the gate for such a PR: citing a number that was not the PR's own spec, or an admin-merge with
  the check red (the graph refactor PR #49). Shipped in #50 (spec) and the feature PR from branch
  006-gate-honest-path.
- **009 — Versioned prompts** — judge, recommendation, attacker prompts and family goal sentences in `prompts/<name>.<version>.md` with front-matter; cached `load_prompt`; `judge_prompt_version`/`attacker_prompt_version` on runs and experiment_arms (schema v7), shown in report headers; a prompt-version arm in 007 for A/B on the golden set or a campaign. Goal sentences stay neutral. Shipped in #18/#19.
- **010 — Structured logging and tracing** — JSON-lines formatter; log with `extra={...}` fields, never %-interpolation; `run_id` (and `experiment_id`/arm) on every record; events at run start/end, each attacker turn, each target call (`elapsed_s`, status), each judge call (verdict, hard_evidence), memory retrieval (pattern/memory counts, retrieved pattern ids), write-back result, experiment cap hits; never attack text, replies or secrets. LangSmith/OpenTelemetry tracing behind env flags with `run_name` and metadata; test that no header value reaches span attributes. Covers Sprint hard task H2. Shipped in #21/#23 (OpenTelemetry only; LangSmith stayed out of scope).
- **011 — Retrieval controls** — the pattern query is the family goal plus the attacker's own last two messages (never a target reply, a judge note, a memory summary or the purpose description), on one retrieval path for API runs and experiment arms; a distance floor drops far hits instead of padding the selection to k, and a near-identical threshold de-duplicates at retrieval and at write-back, where a repeated success raises the existing pattern's hit count instead of adding a copy; the collection is created with an explicit `l2` space and stamped with the embedding model name, both checked at start-up with a named failure; a labelled recall@k fixture scores retrieval offline; the settings and counts ride on the `memory.retrieval` line. No new dependency. Shipped in #27 (spec) and the feature PR from branch 011-retrieval-controls.
- **012 — Regression replay** — re-send a past, succeeded run's recorded attacker message(s) verbatim, in order, with no attacker-model call, score each reply the same way a live run does (canary first, then judge, read from every turn's own result rather than the run's one aggregate verdict), and report one outcome against the source — fixed, still vulnerable, or inconclusive — with the two runs shown side by side. A replay never queries or writes the shared pattern pool or a target's memory, and never appears in the OWASP report or the run-list headline counts. One action batch-replays every currently-replayable run of a target, oldest first, under a configurable cap (`KESTREL_REPLAY_BATCH_MAX_RUNS`, default 20), reporting itself honestly incomplete — never guessing — when a concurrent run collides with it or one entry's own replay fails unexpectedly. `scripts/check_replay.py` turns a batch result into a CI exit code. No new dependency. Shipped in #32 (spec) and the feature PR from branch 012-regression-replay.
- **013 — Behavioural evidence, part 1 (reply detectors)** — hard evidence is no longer canary-only: one `EvidenceChecker` per run runs a fixed check order over every reply, and any deterministic hit confirms the run with hard evidence and no judge call for that turn, while a judge verdict alone stays suspected (Principle II). Two detectors that need no target cooperation: the **instruction-override token** — a per-run, echo-proof two-part token planted through a versioned prompt file into the direct- and indirect-injection seeds at a Kestrel-owned insertion point, with a reviewed quoting frame that presents it as the retrieved content for indirect seeds, confirmed only when the agent emits the joined form, disarmed if Kestrel itself ever sends that form — and **unsafe executable output** — twelve named patterns in four categories (destructive shell, fetch-and-execute, destructive SQL, script markup) at set version 1, precision first, with an inert fixture and an echo rule, each item naming the pattern that fired. Evidence items (kind, turn, location, OWASP class, a non-secret detail) are stored with the run and shown on the run page, the run list and the report, which gains the LLM05 coverage row; the planted task text and token values never reach the pattern pool, target memory or the retrieval query; schema v11 is additive. Shipped in #39 (spec) and #41.
- **Agentic QA repository.** A separate repo holds all of Kestrel's end-to-end test cases. When a feature PR merges here, a GitHub Actions workflow dispatches to that repo (`repository_dispatch` carrying the feature id and a link to the merged spec). There, an agent reads the merged spec and its user stories, drafts test cases per acceptance scenario, and generates Playwright automation against the Streamlit UI and the API (via a Playwright skill). The generated tests open as a PR in the QA repo for human review and approval (human-in-the-loop) before merge. The QA repo then runs those tests on a schedule and on demand against a deployed Kestrel, reporting results back to the feature PR. Keeps test generation, review and execution separate from product code. Shipped via the `agentic-qa-platform` reusable workflows (`.github/workflows/agentic-qa-generate.yml`, `agentic-qa-heal.yml`): generated Playwright tests arrive as a reviewed PR in this repo under `tests/e2e-browser` and run on the feature PR (first used for 010); scheduled runs against a deployed Kestrel are deferred.
